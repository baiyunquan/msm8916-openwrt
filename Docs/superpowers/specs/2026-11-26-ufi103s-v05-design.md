# UFI103S-v05 OpenWrt Profile Design

## Intent

Add a separately selectable OpenWrt target for UFI103S-v05 so CI can build its images. The hardware is reported to share the UFI001C board wiring, and the pmOS tree contains the matching Linux 6.12 DTS.

## Goals

- Add `ufi103s-v05` as a distinct board profile and manual build choice.
- Reuse the UFI001C GPIO assignments: reset GPIO37 active-low; WLAN GPIO20; WAN GPIO21; power GPIO22; SIM controls GPIO0-3.
- Size the generated OpenWrt GPT for the device's measured 7,634,944 sectors.
- Keep the normal OpenWrt image and EDL build flow so GitHub Actions can compile the board.

## Non-goals

- Do not flash the device or modify its GPT/boot chain during this change.
- Do not claim OpenWrt hardware boot or peripheral validation from a CI build.
- Do not change existing UFI001B or UFI003 profiles.

## Approaches

- Reuse `generic-ufi001b`: rejected because its reset polarity, LED roles, and SIM GPIO handling differ from the UFI001C DTS the pmOS device successfully boots.
- Reuse `generic-ufi003-mb-v02`: rejected because it represents a different board and does not establish UFI103S-v05 identity.
- Add `generic-ufi103s-v05` with a board-specific DTS based on the pmOS UFI001C 6.12 GPIO layout: selected because it gives the board its own build target while retaining the known wiring.

## Constraints and implementation calls

- The target uses a unique `thwc,ufi103s-v05` compatible and retains `thwc,ufi001c` as a fallback compatible.
- The OpenWrt GPT recipe uses 7,634,944 sectors, as read from the connected device.
- The profile inherits the existing UFI001B package set; no board-specific package behavior is inferred.
- A successful CI build proves the profile and image compile. Hardware sign-off remains pending.
