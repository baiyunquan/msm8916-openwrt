# UFI103S-v05 OpenWrt Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a buildable UFI103S-v05 OpenWrt target based on the UFI001C wiring and start its single-board GitHub Actions build.

**Architecture:** Add a dedicated board DTS and target profile, register the DTS in the MSM8916 image tree, mirror the UFI001B diffconfig/package baseline, and expose the board in the manual build workflow. Preserve the existing OpenWrt image machinery while setting the verified eMMC size.

**Tech Stack:** OpenWrt image Makefile, Linux 6.12 DTS patch, diffconfig, shell validation suite, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-26-ufi103s-v05-design.md`

## Global Constraints

- Do not flash the device or modify its GPT/boot chain during this change.
- Use reset GPIO37 active-low; WLAN GPIO20; WAN GPIO21; power GPIO22; SIM controls GPIO0-3.
- Set `GPT_TOT_SECTORS := 7634944`.
- Keep the existing UFI001B and UFI003 profiles unchanged.
- CI build is compilation evidence only; hardware sign-off remains pending.

## Review Focus

- Diffconfig, target name, build workflow option, and DTS build registration must use the same `ufi103s-v05` board identity.
- The DTS must preserve the UFI001C button, LED, and SIM GPIO wiring.
- The GPT recipe must use the measured eMMC sector count.
- Existing UFI001B and UFI003 definitions must remain unchanged.
- The dispatched GitHub build must target only `ufi103s-v05`.
